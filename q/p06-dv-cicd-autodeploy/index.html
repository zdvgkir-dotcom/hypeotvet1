Что такое CI/CD и как настроить автодеплой при пуше в GitHub?

Разработка и сайты1 мин чтения
КороткоCI (непрерывная интеграция) автоматически проверяет код тестами и сборкой при каждом коммите, а CD (доставка) сама выкладывает обновлённую версию на сервер. Самый простой способ — бесплатный файл GitHub Actions в папке .github/workflows.

Зачем нужен автодеплой

Ручная заливка файлов по FTP часто приводит к ошибкам: забыли скопировать один файл, перезаписали .env или сломали продакшен несобранным кодом. CI/CD делает выкладку предсказуемой и повторяемой.

Как работает пайплайн на GitHub Actions

  1. Вы делаете git push в ветку main.
  2. GitHub запускает виртуальную машину по сценарию из файла .github/workflows/deploy.yml.
  3. Шаг CI: устанавливаются зависимости, прогоняются npm test и npm run build. Если есть ошибка — процесс останавливается, рабочий сайт не затронут.
  4. Шаг CD: готовая сборка отправляется на GitHub Pages, в облако или на ваш VPS по SSH с перезапуском сервиса.
SSH-ключи, пароли и токены для деплоя храните только в разделе Settings → Secrets and variables → Actions репозитория, а не в самом YAML-файле.
