Как просить ИИ писать тесты и проверять свой же код?

Вайбкодинг бесплатно1 мин чтения
КороткоПросите писать тесты по конкретным бизнес-сценариям и крайним случаям (пустой ввод, ошибки сети, отрицательные числа) и обязательно запускайте их в терминале. Для критичной логики проверяйте, что тест падает, если намеренно сломать функцию.

Ловушка «зелёных» тестов от ИИ

Если просто сказать «напиши тесты», модель иногда подгоняет тест под существующий баг или мокает саму проверяемую функцию. Такой тест всегда зелёный, но ничего не защищает.

Как ставить задачу на тестирование

  1. Unit-тесты для логики: Vitest/Jest для JS и Pytest для Python. Перечислите 5-7 граничных случаев: 0, отрицательное число, пустая строка, невалидный формат, дубликат.
  2. E2E-тесты для ключевого пути: Playwright. Один сценарий: «открыть сайт, заполнить форму, нажать Отправить, увидеть сообщение об успехе».
  3. Запрет на подгонку: добавьте в промпт правило «Если тест упал, сначала объясни, ошибка в коде или в тесте; не ослабляй проверки, чтобы тест прошёл».

Приём самопроверки

В агентном режиме дайте команду: «После каждой правки запускай npm test и npm run build; не завершай задачу, пока обе команды не вернут код 0». Это резко снижает число регрессий.
