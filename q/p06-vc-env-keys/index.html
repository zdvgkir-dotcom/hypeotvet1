Как правильно хранить API-ключи в .env и не слить их на GitHub?

ХайпВайбкодинг бесплатно1 мин чтения
КороткоХраните все секреты в файле .env, сразу добавьте .env в .gitignore и никогда не передавайте приватные ключи во фронтенд-код браузера. В репозиторий кладите только шаблон .env.example с пустыми значениями.

Почему утечка ключа происходит за минуты

Автоматические боты непрерывно сканируют публичные репозитории GitHub. Если вы закоммитили ключ OpenAI, Telegram-бота или платёжного шлюза, его найдут и используют за 2-5 минут.

Правильная схема работы

  1. Создайте в корне файл .env со строками вида BOT_TOKEN=ваш_секрет.
  2. Добавьте в .gitignore строки .env и .env.*, кроме !.env.example.
  3. Создайте .env.example с именами переменных без реальных значений — ИИ сможет читать его для понимания конфигурации.
  4. Вызывайте сторонние API только с бэкенда (серверные маршруты), чтобы ключ не попал в бандл браузера. Переменные с префиксами VITE_ или NEXT_PUBLIC_ видны всем пользователям!

Что делать, если ключ уже попал в Git

Простое удаление файла новым коммитом не поможет — ключ останется в истории Git. Сразу перевыпустите (отзовите) ключ в личном кабинете сервиса, а затем очистите историю репозитория.

В настройках AI-редактора добавьте .env в .cursorignore или аналог, чтобы секреты не отправлялись в контекст облачной модели.
